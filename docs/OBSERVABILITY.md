# 对话与网络可观测性

最后更新：2026-09-08

## 已实现（第一、二阶段）

- 任务监控默认不显示对话名称，只显示估算上下文占用、缓存命中、完整一轮输入/输出和当前运行时间；完整一轮优先读取 `turn_token_usage`，不能把单次模型请求的 `last_token_usage` 误标成整轮。
- “详情”读取本机 Codex JSONL，展示累计、输入、缓存、新增输入、输出、推理、缓存复用率、上下文和其他对话。
- 会话解析只读取文件头和末尾最多 4 MB，并缓存最多 200 个结果，不复制或修改 Codex 会话。
- 系统监控默认显示实时下载、上传、当前网卡和 Mihomo/Clash 摘要。
- 网络详情显示代理进程、当前节点、TUN、GNOME 系统代理和 Control Tower 进程继承的终端代理变量。
- Mihomo 控制接口只尝试本机 `127.0.0.1:9090/9097`，不可读时显示未知，不猜测节点。

上下文占用使用最近请求输入 Token 除以模型上报的上下文窗口，是近似值；压缩发生后不应理解为项目级上下文占用。

## 已实现（第三、四阶段）

- 手动检测 Codex、GitHub、Hugging Face 可达性、HTTP 状态和延迟。
- 结合 Mihomo Connections 显示 Codex、GitHub、Hugging Face、SSH 的实时规则和代理链；没有活动连接时明确显示为空。
- 支持 Mihomo TCP Controller 和 Clash Verge/Mihomo Party 使用的 Unix Socket Controller，控制密钥只在内存中读取和使用。
- 手动测试当前线路的 3 MB 下载、128 KB 上传、TTFB、稳定性和失败率，结果在内存中缓存 10 分钟。
- `Codex 加速`、`代码下载加速`、`模型下载加速`分别在对应 Mihomo 策略组中测试最多 12 个候选节点，并直接切换到目标服务延迟最低的节点。Codex 使用独立 AI 策略组；当前 GitHub 与 Hugging Face 共用主策略组，因此二者最后一次切换会覆盖前一次。
- `代码下载加速`以 GitHub 为测速目标，`模型下载加速`以 Hugging Face 为测速目标；界面会移除节点名称开头无法被 Qt 字体渲染的旗帜/Emoji，但切换时仍使用原始节点名称。

## 产品约束

- 默认页面展示结论，详情展示数据，诊断解释原因。
- 不为监控信息增加横向滚动。
- 任务监控和学习页面采用低饱和浅色分区；高饱和颜色只用于需要用户注意的异常状态。
- 不上传项目路径、对话内容、代理配置或连接记录。
- 高频网络样本只保存在内存；未来持久化测速记录时必须设置数量和期限上限。
- 网络诊断、真实测速和一键加速只能手动触发；测速结果仅在内存中缓存 10 分钟。
