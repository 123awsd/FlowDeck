# 领域学习系统设计

状态：前沿追踪已实现；VLA 系统学习与 3～5 分钟微课层已实现
最后更新：2026-09-06

## 目标

建立一条可以复用于 VLA、VLN、WAM、RL、UAV 等方向的领域学习 pipeline：

> 可靠资料 → 一次性编译知识框架 → 人工审查冻结 → 生成微学习卡 → 日常按顺序学习 → 前沿只提供增量补丁。

这里的核心资产不是每天生成的摘要，而是一份可以稳定使用数周或数月、能够审查和版本管理的 Curriculum。

## 两种学习模式

### 前沿追踪（已实现）

回答“今天这个领域出现了什么值得注意的新内容”。特点是动态、开放、跨来源和持续更新。

- 宽召回 arXiv、GitHub、Hugging Face 和官方 Demo；
- 经过范围相关度、质量门槛、五通道评分、去重和多样性重排；
- 兴趣只影响排序，不是候选白名单；
- 可以关联到已有 Concept，但不能自动修改 Curriculum。

### 系统学习（已实现）

回答“为了建立稳定认知，我接下来应该学什么”。特点是稳定、有前置关系、有顺序和可记录进度。

- 页面显示中性名称“系统学习”；
- 第一批专项路线为 `VLA`、`VLN`、`WAM`，不使用过泛的“具身智能路线”；当前已导入 VLA，VLN/WAM 保留待导入入口；
- 公共节点跨路线复用，避免重复学习；
- 默认按冻结框架推进，只允许用户主动跳转；
- 不在显眼 UI 中出现“面试”“求职”或岗位名称，但卡片可以帮助技术表达与问答。
- 知识点正文固定采用“直觉 → 机制 → VLA 例子 → 方法辨析 → 易混点 → 论文术语 → 自测”，不能直接拿 `scope`、`learning_goals` 等框架元数据充当教材；
- 关键课可随课程包提供人工审查过的 `lessons_v1.json`；其余课程首次阅读时后台生成，并预取下一课；
- 生成结果写入最多 300 条的本地缓存，切换知识点不触发 VS Code、账号或 Codex 会话的全量扫描。
- 每节课提供独立的“和 AI 讨论”窗口，允许围绕当前微课自然语言连续追问；只发送当前 Concept、Lesson、来源标题及该知识点最近 12 条问答，不发送项目路径、账号或 Codex 对话。
- 问答记录写入本地 `data/curriculum_chats.json`，每个知识点最多 40 条、全局最多 1200 条，可从对话窗单独清空。

## 完整 pipeline

1. 选择一个边界明确的领域，例如 VLA。
2. 找到 2～4 篇高质量 Survey、1～2 门相关课程/教程、1～2 个持续更新的 curated repo；不足时可补少量奠基论文。
3. LLM 只负责提取目录、合并、去重、建立前置依赖和标注优先级。
4. 使用独立审稿视角检查遗漏、粒度、顺序、热点偏置和依赖环，并据此修订。
5. 用户人工检查关键取舍，通过后冻结为 `Curriculum v1`。
6. 基于冻结节点生成 3～5 分钟卡片，而不是每天重建目录。
7. Codex 运行时，用户按 Curriculum 顺序消费知识。
8. 论文或项目中遇到陌生概念时，先进入候选收件箱，由用户决定是否插入。
9. Frontier Feed 发现的新趋势只作为补丁候选并关联现有 Concept。
10. 每 1～3 个月或出现重大范式变化时，人工触发 `v1 → v2` 审查。

## 核心对象

### Domain

一个边界明确、可以单独维护版本的方向，例如：

- `vla`：Vision-Language-Action；
- `vln`：Vision-Language Navigation；
- `wam`：面向机器人的 World Action Model；
- 未来可增加 `rl`、`uav` 等。

### Curriculum

包含模块、知识节点顺序、优先级、前置依赖、推荐路径、来源和版本状态。

建议状态：

```text
draft → reviewed_draft → frozen → superseded
```

只有 `frozen` 版本可以作为日常默认学习路线。升级版本必须保留稳定 Concept ID，以便迁移进度。

### Concept

最小可学习单元，例如 `flow_matching`、`action_chunking`。每个节点包含：

- 中英文名称；
- 所属模块和顺序；
- `P0 / P1 / P2` 优先级及理由；
- `foundation / evolving / frontier` 稳定性；
- 前置节点和相邻节点；
- 学习目标、识别关键词和代表工作；
- 可追溯的来源 ID；
- 3～5 分钟卡片。

个人掌握状态计划为：

```text
未学习 → 学习中 → 已理解 → 可深入
```

“还不清楚”不强制推进节点，并进入复习队列；“深入”展开公式、论文或代码，不改变基础卡片长度。

### Frontier Event

论文、代码、模型和 Demo 合并后的前沿事件。它可以：

- 关联一个或多个已有 Concept；
- 提示某个未学习节点；
- 进入 Curriculum Patch Inbox；
- 在人工批准后参与下一个版本的框架审查。

它不能直接新增、删除或重排冻结 Curriculum 中的节点。

## 当前目录结构

前沿推荐偏好位于 `config/learning_preferences.json`，运行数据库位于 `data/learning.db`。领域知识资产已经使用下面的结构：

```text
learning/
├── README.md
├── domains/
│   ├── vla/
│   │   ├── sources.json
│   │   ├── curriculum_v1.json
│   │   ├── curriculum_v1.md
│   │   ├── review_v1.md
│   │   └── cards/
│   ├── vln/                 # 待导入时创建
│   └── wam/                 # 待导入时创建
└── inbox/                   # 有候选补丁时创建
```

版本管理规则：

- `domains/`：长期知识资产，进入 Git；
- `inbox/`：待人工判断的候选补丁；
- 个人进度、反馈、复习队列和缓存统一保存到仓库现有的 `data/`，并加入 `.gitignore`；
- API Key 始终位于 `.env`。

## Curriculum 编译交付契约

每个新领域首先交付四份文件：

1. `sources.json`：经过核验的 Survey、课程、Repo 和补充论文；
2. `curriculum_vN.json`：程序读取的合法 JSON；
3. `curriculum_vN.md`：供用户人工审查的可读版本；
4. `review_vN.md`：初稿问题、接受/拒绝的审查意见和冻结理由。

正式接入前必须验证：

- JSON 能被解析；
- module、concept、source ID 唯一；
- 所有引用指向真实对象；
- prerequisite 图无环且顺序合理；
- 每个 Concept 至少有一个可靠来源；
- P0 数量克制；
- 示例模型没有被误当成发现范围的白名单；
- 用户已经看过 Markdown 版本中的关键取舍。

## VLA 首次试运行

VLA 四份交付物已经从网页版 GPT 导入：18 个来源、7 个模块、39 个节点。`scripts/validate_curriculum.py` 已确认 JSON、ID、引用、模块归属、推荐路径和 prerequisite DAG 有效。课程仍保持 `reviewed_draft`，没有替用户冻结。

收到文件后的实现顺序：

1. 用户在系统学习页打开完整框架和审查报告，检查关键取舍；
2. 用户点击“确认启用 v1”，只在本地记录确认状态，不静默重写课程文件；
3. 使用少量人工审查卡验证 3～5 分钟学习体验，其余卡片按需生成并本地缓存；
4. 将 canonical Curriculum 状态冻结；
5. 增加复习队列和 Frontier Event → Concept 关联，并复用 pipeline 添加 VLN/WAM。

## 不变原则

- 可靠来源决定“领域里有什么”，LLM 负责整理，不能凭印象自由编目录。
- 知识框架可以高成本、低频更新；日常卡片应低成本、稳定消费。
- 框架必须经过人工冻结，自动系统不能越过这道门。
- Interest 可以改变学习入口和推荐顺序，但不应篡改领域事实结构。
- 允许今天没有值得加入框架的新知识，不为了显得活跃而制造补丁。
